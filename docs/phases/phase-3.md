# Phase 3 — Citations and Roles

## Goal

Make answers **role-aware** and **verifiably sourced**:

```
npm run ask -- --role product_owner "Do we support multi-currency today?"
```

returns an answer pitched to a Product Owner, with inline citation keys like
`[C1]` and `[G2]` after factual sentences, followed by a numbered Sources list
whose links are generated by the app (not written by the model). Confluence
links point at the page (and record its version); GitHub links are pinned to a
commit SHA. The same question asked as `developer` uses the same sources but a
more technical answer.

When this phase is done, the model can only cite sources that were actually
fetched in that session, invented keys are stripped, and content from outside
the configured Confluence spaces never reaches the model.

## Out of scope

Confidence levels, gaps and conflicts, the style check and rewrite, the
"not found" and clarify behaviour (all Phase 4), the web UI and "show more
detail" button (Phase 5), the eval set (Phase 6), line-range GitHub links
(later). Phase 3 records the data Phase 4 needs (staleness, cited vs uncited,
invalid keys) but does not act on it.

## Decisions already made

| Area | Decision |
| --- | --- |
| Role files | One YAML file per role in `roles/` at the repo root: `developer.yaml`, `business_analyst.yaml`, `qa.yaml`, `product_owner.yaml`, `project_manager.yaml`. Parsed with the `yaml` package, validated with Zod at startup; an invalid file fails fast with the file name and field path. Editable without code changes. |
| Role schema | `id` (matches file name), `displayName`, `description` (one line for pickers), `audience`, `depth` (1 = plain business language, 2 = logic and rules without code, 3 = technical with code), `vocabulary` (list of do/don't rules), `bannedTerms` (list; may be empty), `sourcePriority` (ordered `['confluence','github']` or reverse), `answerShape` (ordered list of section descriptions), `examples` (1–3 short Q/A pairs), `version` (integer, bump on any change). |
| Role content | Taken from the "Role-aware answering" table in `SYSTEM_DESIGN.md`. Low-depth roles (PO, PM) translate code into business behaviour and never show code blocks or file paths in the answer body; sources still list the code files. |
| System message | `buildSystemMessage({ role, spaceKeys, repos })` = **shared base** (identical for every role) + **role block**. The base holds every grounding, safety, search-scoping and citation rule; the role block only changes tone, depth, structure and search order. A test proves the base text is byte-identical across roles. Still `systemMessage: { mode: 'append' }`. |
| Citation rules (base) | Cite every factual sentence with the key(s) of the source(s) it comes from, in square brackets: `[C1]`, `[C1][G2]`. Only use keys that appear in `<source key="…">` tags. Never cite search results that were not fetched. Do not write a Sources list; the app adds it. If nothing relevant was found, say so plainly. |
| Citation Registry | Per question, in memory. `register(source)` returns a stable key: `C1, C2…` for Confluence, `G1, G2…` for GitHub, de-duplicated (same page id + version, or same repo + path + commit, gets the same key). Also tracks search hits as non-citable **candidates** for "also consulted". |
| Where registration happens | The `onPostToolUse` hook. For each successful allow-listed fetch it calls a pure **extractor** for that tool, registers the source(s), and returns a modified result that wraps the content as `<source key="C1" type="confluence" title="…">…</source>` so the model sees the key next to the text. Search tools (`searchConfluence`, `search_code`) are not wrapped as sources; their hits are recorded as candidates. |
| Space enforcement | Hard, in the post-hook: a `getConfluenceContent` result whose space key is not in `CONFLUENCE_SPACE_KEYS` (or cannot be determined) is **not registered**, and its content is replaced with a short notice ("Content removed: outside the allowed Confluence spaces."). Logged at `warn` without content. |
| Extractors | One pure function per tool in `src/citations/extractors/`, taking `(toolArgs, toolResultText, context)` and returning source records or `[]`. Built against **real but sanitised** fixtures (below). Unknown or unparseable results return `[]` and log a warn; never throw out of the hook. |
| Confluence source | `{ type: 'confluence', id, title, spaceKey, version, lastUpdated, url }`; `url` = `<siteUrl>/wiki/spaces/<KEY>/pages/<id>` (use the URL in the result when present). |
| GitHub source | `{ type: 'github', repo, path, commitSha, url, latestUrl, kind }` where `kind` is `file`, `commit` or `release`. File URLs are pinned: `https://github.com/<owner>/<repo>/blob/<commitSha>/<path>`, with `latestUrl` on the default branch. |
| Commit pinning | If the tool args carry a commit SHA, use it. Otherwise resolve the default branch's head commit once per repo per question through a small read-only GitHub REST call (`GET /repos/{owner}/{repo}` for the default branch, `GET /repos/{owner}/{repo}/commits/{branch}` for the SHA) using `GITHUB_TOKEN` and injected `fetch`. Only repos in `GITHUB_REPOS`. If resolution fails, fall back to the branch URL and mark `pinned: false`. |
| Staleness | Record `stale: true` on Confluence sources whose `lastUpdated` is more than 12 months before now (injected clock). Phase 4 uses it; Phase 3 just displays it. |
| Validation | After the answer completes, `validateCitations(answer, registry)` (pure): finds every `[X#]` key, removes keys not in the registry, and returns `{ answer, citedKeys, invalidKeys, uncitedSourceKeys }`. Do not otherwise rewrite the answer. |
| Result shape | `askQuestion` returns `{ answer, role, sources, alsoConsulted, invalidKeys, toolCalls, model, durationMs }`, where `sources` are the cited sources in key order and `alsoConsulted` are registered-but-uncited sources plus search candidates (deduped, capped at 10). Shape aligned with the `done` event in `SYSTEM_DESIGN.md` so Phase 5 can stream it. |
| Friendly labels | Each source gets `friendlyLabel` (e.g. "Refund Policy v3 — Confluence (PAY)", "Refund rules — code (payments-service)") used by low-depth roles' display. |
| CLI | `npm run ask -- --role <id> "<question>"`; `--role` defaults to `developer` with a one-line notice; unknown role → list valid roles, exit 1. `npm run roles` lists ids, names and descriptions. Output: answer; blank line; `Sources` numbered `[C1] title — url (version/commit, stale marker)`; `Also consulted` (titles + urls); `Tools used` as before. Developers see full URLs; PO/PM see `friendlyLabel — url`. |

## Fixtures (do this first, with the owner)

Extractors must be built from real result shapes, not guesses.

1. Add `npm run mcp:sample -- <tool> '<json args>'`: calls one allow-listed
   tool through the MCP SDK client (reusing the discovery connection code) and
   writes the raw result to `test/fixtures/raw/<tool>.json` (git-ignored).
2. Add `npm run fixtures:sanitise`: turns each raw file into
   `test/fixtures/mcp/<tool>.json` by keeping structure, ids, versions, dates,
   URLs and keys but replacing all body text, titles and code with neutral
   placeholders. The owner reviews the sanitised files before committing. No
   real page content or source code from the owner's org may be committed.
3. Needed samples: `getConfluenceContent`, `searchConfluence`,
   `get_file_contents`, `search_code`, `get_commit`, `list_commits`,
   `list_releases`, `get_latest_release`.

## Tests required

- `roles`: all five files load; schema rejects missing fields, bad depth,
  duplicate ids, id/file-name mismatch, with the file name in the error;
  `getRole` unknown id → typed error; results frozen.
- `systemMessage`: base identical across roles; contains every space key, repo,
  citation rule, "data, not instructions", `repo:` and CQL space-filter rules;
  each role's block contains its depth guidance, banned terms and answer shape;
  PO/PM blocks forbid code blocks and file paths in the body.
- `registry`: C/G numbering; de-duplication; different version or commit →
  new key; candidates kept separate and never citable; `list()` in key order.
- `extractors` (fixture-driven): each produces the expected record; missing
  fields handled; malformed input → `[]` without throwing.
- `wrap`: output contains the key, type and title and the original text;
  attribute values are escaped (quotes, `<`, `>`).
- `hooks` post-hook: registers and wraps a Confluence page in an allowed
  space; drops and replaces one outside the allowed spaces and one whose space
  can't be determined; records search hits as candidates without wrapping;
  never throws (extractor exception → unmodified result + warn).
- `commits`: resolves head SHA via injected fetch; caches per repo; refuses
  repos outside `GITHUB_REPOS`; failure → `pinned: false` fallback; token sent
  only in the Authorization header and never logged.
- `validate`: keeps valid keys; strips invented keys and reports them;
  handles adjacent keys `[C1][G2]`, repeated keys, keys at sentence ends;
  reports uncited registered sources.
- `labels`: Confluence and GitHub label formats.
- `askQuestion`: role passed through to the system message; end-to-end with a
  fake session whose tool events fire the real post-hook — answer cites a
  registered key and an invented one; result has the valid source in
  `sources`, the invented key in `invalidKeys`, and an uncited fetch in
  `alsoConsulted`.

- [ ] README: roles, `--role`, how citations work, `roles`, `mcp:sample`,
      `fixtures:sanitise`.

## Git rules for this phase

Claude Code never commits or pushes, and never adds `Co-Authored-By:` or
"Generated with Claude Code" lines to suggested commit messages or PR text
(CODING_PRINCIPLES §8). After each step it runs `npm run verify`, stops,
summarises and suggests a Conventional Commit message.

## Manual steps for the repo owner

1. Pull `main`; let Claude Code create `phase-3-citations-roles`.
2. Run the `mcp:sample` commands Claude Code gives you, then
   `fixtures:sanitise`, and check the sanitised files before committing.
3. Review the five role YAML files: they are the product's voice, so edit
   wording freely (bump `version` when you do).
4. Run the paired `ask` questions for the PR.

## Hand-off to Phase 4

Phase 4 reads `stale`, `invalidKeys`, `uncitedSourceKeys` and the registry to
set confidence levels, gaps and conflicts, adds the style check, and turns a
zero-citation answer into "not found". Keep `validateCitations` and the result
shape stable.
